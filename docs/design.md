# ゲームデザイン

## 1. 制約がゲームになっている

太郎はPCが見えるものしか見えない。
この一行から、UIも、ゲーム性も、章構成も全部導かれる。

- PCのカメラがONなら → 顔・姿勢・部屋が見える → **観察のゲーム**
- カメラがOFFなら → 文字しか届かない → **傾聴のゲーム**
- PCが閉じられていれば → 何も見えない → **時間が飛ぶ**

華子が何時に帰ってきたかは、PCが起動した時刻でわかる。
何に悩んでいるかは、検索窓に打ちかけて消した文字でわかる。
太郎は覗いているのではなく、それしか見えないから見ている。

この制約は絶対に緩めない。
「太郎が心配で部屋を見に行く」のような描写を一度でも入れると、
以降プレイヤーは情報が足りないことを演出の手抜きだと感じるようになる。

## 2. 三つのモード

### 華子編 (カメラON / 本編90日)

画面に華子が映っている。プレイヤーは見て、選ぶ。
見えるもの: 表情、姿勢、帰宅時刻、食事の有無、PC上の行動（検索・購入・SNS）。
選択肢は多くない。多くの日は、話しかけるか、話しかけないか。

### 出張編 (カメラOFF / 本編中に挿入)

チャットのみ。相手の顔は見えない。名前も年齢も自己申告。
相手は太郎を「AI相談窓口」だと思っている。太郎の正体を知らない。
だから相手は遠慮なく症状を訴え、同時に都合の悪いことは書かない。

### 癒しマンONLINE (クリア後)

出張編と同じUIをそのまま流用したエンドレスモード。
UIを流用することに意味がある。
本編を終えたプレイヤーが同じ画面を見たとき、
かつて太郎がここにいたのだと気づく作りにする。

## 3. 設問の密度 — この作品で一番重要な設計判断

**90日すべてに設問を置かない。**

全日に設問を置くと、プレイヤーは「今日も選ばされる」という義務感を持つ。
義務でこなす日が続くと、選択肢の重みが均される。
その結果、本当に重い日が来ても重く感じられなくなる。
つまり全日設問は、この作品の核である「変化に気づく」体験を殺す。

日を三段階に分ける。

### 節目の日 — 12〜15日

重い設問を置く。外れ選択肢を必ず含める。
外れを選ぶと信頼度が下がり、華子は `face: 05` で目をそらす。
踏み込みすぎた場合は `face: 04`。

節目の条件:
- 華子の状態が段階的に悪化する境目
- 太郎の価値観が揺らぐ日（神様との対話を含む）
- 出張編で学んだ知識が回収される日

### 観察の日 — 40日前後

軽い選択を置く。ここでは**外れを作らない**。
「雑談する」「放っておく」も正解になり得る。
放っておくことが正解になる日を必ず含める。
これがないと、プレイヤーは「常に介入するのが善」だと学習してしまい、
本作が否定したい「頑張り続ける価値観」をプレイヤー側で再生産することになる。

### 凪の日 — 残り 35日前後

設問なし。数秒で流れる。
何も起きない日を描くのは手抜きではなく、異変の日を際立たせるための土台である。
凪の日にも `face` は設定する。凪が続く中で表情だけが 01 → 02 に変わっていることに
プレイヤーが自力で気づく、その瞬間がこの作品の一番おいしいところ。

### 配置の原則

- 節目を連続させない。節目の直後は必ず凪か観察を挟む
- 凪を4日以上連続させない。だれる
- 終盤（Day 70以降）は節目の密度を上げてよい

具体的な配置日は未決定。決定するまで本文は書かない。

## 4. 出張編の設計

華子編とは逆に、設問を多くする。
情報が文字しかない分、質問という能動的行為の回数で密度を作る。

### 1ケースの流れ

1. 相手の第一声（属性は名乗るが、症状の全体像は言わない）
2. **質問パネル: 16問前後。選べるのは5問前後**
3. 対応判断: 様子見 / 生活改善 / 受診勧奨 / 緊急
4. 医学的・心理学的な解説

### 質問数を絞ることが肝

16問中5問。この比率を守る。
全部聞ければ誰でも正解できてしまい、それは傾聴ではなく総当たりである。
限られた枠をどこに使うかを選ばせることで、初めて「聴く力」が問われる。

質問パネルの内訳の目安:
- 決定的な情報を引き出す質問: 2〜3問
- 有用だが決定打ではない質問: 5〜6問
- もっともらしいが無駄な質問: 5〜6問
- 相手を萎縮させる質問（聞くと以降の回答が短くなる）: 1〜2問

無駄な質問は「いかにも医療っぽい」ものにする。
医療知識があるプレイヤーほど引っかかる形にすると、傾聴と診断の違いが体験として出る。

### 華子編への伏線

本編中に20〜30ケース。うち**5ケースは華子編の節目に効く伏線**とする。

例: 「片側だけの腫れと痛みは軽く見ない」を出張ケースで学ぶ。
後日、華子が片脚をさすっている描写が凪の日に混ざる。
出張編をちゃんとやったプレイヤーだけが、その凪を凪ではないと見抜ける。

伏線ケースは `foreshadow` フィールドで、効かせる華子編の日と紐付ける。
伏線ケースは必ず、対応する華子編の日より**前**に出す。順序は実装側で検証する。

## 5. パラメータ

| 名前 | 動き | 用途 |
|---|---|---|
| 信頼度 | 外れで下がる。回復は遅い | 華子が本音を話すかの閾値 |
| 癒しポイント | 正解方向で貯まる | エンディング分岐 |

数値レンジと閾値は未定。節目の配置が決まってから逆算する。
先に数値を決めると、シナリオが数値合わせになる。

## 6. 太郎の転換点

序盤の太郎は華子に共感する。「わかる、俺もそうだった」と。
太郎は同じ価値観で死んだ人間なので、これは太郎にとって自然な反応である。
そして、これがプレイヤーにとっての罠になる。
共感は気持ちがいい。だから最初の数十日、プレイヤーは太郎と一緒に間違える。

神様が「お前、それで死んだんじゃが」と指摘する日が転換点。
ここで太郎は、自分が華子にしていたことが延命ではなく同伴だったと気づく。
以降、太郎の台詞のトーンが変わる。共感から、問いへ。

この転換の前後で、同じ選択肢の正解が入れ替わる日を最低1組作る。
「頑張ってるね」が前半は正解で、後半は外れになる。
プレイヤーに、自分の価値観が変わったことを自分で確認させる。

## 7. ラスボス

「限界まで頑張ることが偉い」という価値観。
人格を持たせない。上司も会社も、この価値観の運搬役にすぎない。
悪役として上司を描かない。上司自身も同じ価値観の被害者であることが分かる描写を入れる。

## 8. エンディング

華子が転職して笑顔を取り戻す (`face: 06`)。
太郎が成仏する。
数年後、太郎は華子の子として生まれ変わる。
将来ネット相談サービス『癒しマン』を始めるところまで描く。

出張編で相手が太郎を「AI相談窓口」だと思っていたことが、
ここで一周する。
